# Contributing

Voice Kit is an experiment. Contributions are most useful when they improve the workflow or add honest evidence about where it succeeds and fails.

## Share a field report

Open an issue describing:

- the kind of writing task;
- the mode or modes used;
- what new thinking the interaction produced;
- whether the writer could explain and defend the result;
- where the output did or did not sound like the writer; and
- which friction felt generative or administrative.

Do not include private source material, confidential work details, or writing you do not have permission to share.

## Propose a workflow change

Explain the observed problem before proposing new instructions. A useful change should say:

- what behavior it changes;
- which mode it belongs to;
- what evidence motivated it; and
- what tradeoff or failure mode it may introduce.

## Pull requests

Keep changes small and readable. Preserve the model-independent Markdown format unless a separate implementation is clearly identified as an example. Avoid adding a new mode when an existing mode can express the behavior.
